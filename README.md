# tofu

Homelab service management: run self-hosted services in a code-like, reproducible, maintainable way. This repository commits only service declarations and docs — never data or secrets.

- One self-contained directory per service: `services/<name>/` (`compose.yaml` + `.env.example` + config template + `README.md` ops manual)
- Single command entrypoint via **just**
- **pi agent** assists per `AGENTS.md`; docker operations are executed by the dev/owner on the target machine
- First service: private git (**Gogs**); every service ships a design doc first (`docs/<name>-design.md`)

## Quick start

Prerequisites: `just`, `dprint`, `docker` (install notes in `AGENTS.md`).

```bash
just list        # services & container state
just bootstrap   # create missing .env from .env.example
just doctor      # environment self-check
```

## Common commands

| Command                   | Purpose                                                                   |
| ------------------------- | ------------------------------------------------------------------------- |
| `just fmt`                | Format repo files (dprint: md/toml/json)                                  |
| `just check`              | Format checks (dprint + justfile self-check); must be green before commit |
| `just ci`                 | CI aggregate entrypoint (run by GitHub Actions)                           |
| `just <service>-<action>` | Service-level ops once a service lands (see its README)                   |

## Layout & conventions

- `services/<name>/`: service declarations; `.env` is generated by `just bootstrap`, never committed
- `docs/<name>-design.md`: design-doc-first, records decisions & rationale
- Environments: production Linux VM, test macOS (Docker Desktop); same compose/`.env` templates, differences only in `.env` / `data/` (one umbrella for runtime data and backups)
- Toolchain direction: Rust + TS (no TS yet; no Python tooling)
- Formatting: dprint (`dprint.json`, pinned plugins); lint/format gate: `just check`
- CI: `.github/workflows/ci.yml` runs `just check`
- `.env`, `data/` (runtime data + backups under one umbrella), `*-draft.md` are gitignored (see `.gitignore`)
- git: no branch switching; approval required before commit; the owner pushes manually after human review (see `AGENTS.md`)
